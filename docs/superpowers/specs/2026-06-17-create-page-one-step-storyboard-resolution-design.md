# 新建页一步生成分镜与分辨率回归设计

## 背景

当前新建页是两步流程：用户先输入产品想法并点击“生成内容规划”，再点击“用当前规划生成分镜”。这会让实际操作多一次确认，也容易出现输入想法已变化但仍使用旧规划生成分镜的情况。

本次改造目标是把“内容想法”和“内容规划”合并为一个用户操作：用户填写“内容规划想法”后，点击一个主按钮即可生成对应分镜。系统内部仍保留内容规划作为中间产物，用于保证分镜质量和可追溯性。

同时补充 `480p`、`720p`、`1080p` 的请求格式回归测试。之前出现过 `480p` 入参格式不符合接口要求的问题，本次测试要确保对 ToAPIs 和官方即梦请求都传小写合法值。

## 范围

包含：

- 新建页主流程从两步按钮改为一步按钮。
- 输入区文案从“产品想法”调整为“内容规划想法”。
- 点击主按钮后，系统先生成内容规划，再自动生成默认 6 个分镜。
- 内容规划结果继续展示，但降级为辅助查看/调试区域，不再作为用户必须点击的步骤。
- 增加分辨率请求格式测试，覆盖 `480p`、`720p`、`1080p`。
- Fast 模型不做前端禁用或自动降级。如果用户选择 Fast 模型并提交其不支持的分辨率，例如 `1080p`，系统按用户选择正常提交，由官方接口返回错误，页面展示该错误。

不包含：

- 不改变 Fast 模型的分辨率选项。
- 不对 `1080p` 做自动降级到 `720p`。
- 不改动产品图上传结构和参考图用途标记，本部分沿用现有实现。
- 不改动视频任务审核页主流程。

## 用户流程

1. 用户进入“新建内容规划”页面。
2. 用户填写“内容规划想法”，并配置产品图、分辨率、生成数量等现有字段。
3. 用户点击“生成分镜脚本”。
4. 系统检查输入内容：
   - 如果没有可用内容规划，先生成内容规划。
   - 如果当前输入想法与最近一次内容规划使用的想法不同，重新生成内容规划。
   - 如果当前输入想法未变化且已有内容规划，可以复用当前规划。
5. 内容规划生成成功后，系统立即使用该规划生成默认 6 个分镜。
6. 页面展示分镜草稿，用户可编辑后进入审核生成视频。

## 页面设计

新建页保留现有纵向结构，但按钮层级调整：

- 输入面板：
  - 标签改为“内容规划想法”。
  - 文本框仍绑定 `contentBrief.seed`。
- 规划结果面板：
  - 继续展示模型返回的内容规划。
  - 操作按钮不再作为主流程入口。
  - 可保留“重新生成规划”作为辅助操作，但不能成为生成分镜的前置必点步骤。
- 分镜面板：
  - 主按钮改为“生成分镜脚本”。
  - 主按钮触发一体化动作：生成/复用规划，然后生成分镜。
  - “进入审核生成视频”仍然只在已有分镜后可用。

## 数据流

沿用现有任务结构，不新增独立任务类型：

- 内容规划继续使用现有 content plan task。
- 分镜继续写入最近一次规划任务。
- 为避免旧规划误用，需要记录或比较最近一次规划对应的输入想法。

推荐实现方式：

- 在生成内容规划任务时保存 `contentBrief.seed` 快照。
- 一体化生成按钮触发时比较当前 `state.contentBrief.seed` 和最近规划任务里的 seed 快照。
- 不一致时先重新生成规划，再生成分镜。
- 一致且已有 `contentPlan` 时直接生成分镜。

## 接口与错误处理

分辨率统一通过现有归一化逻辑处理：

- 合法值为 `480p`、`720p`、`1080p`。
- 大小写输入先转换为小写。
- 非法或空值回退到 `720p`。

ToAPIs 请求：

- `body.resolution` 必须传小写值。

官方即梦 Seedance 请求：

- `body.parameters.resolution` 必须传小写值。

Fast 模型特殊情况：

- 页面不提前屏蔽 `1080p`。
- 请求仍按用户选择提交。
- 如果官方接口返回“该模型不支持该分辨率”之类错误，页面按现有 provider 错误展示机制显示。

## 测试计划

核心测试：

- `480p`、`720p`、`1080p` 在 ToAPIs 请求中分别输出为 `body.resolution`。
- `480p`、`720p`、`1080p` 在官方即梦请求中分别输出为 `body.parameters.resolution`。
- `480P` 等大小写输入归一化为 `480p`。
- 非法值回退为 `720p`。

页面测试：

- 新建页包含“内容规划想法”文案。
- 新建页包含“生成分镜脚本”主按钮。
- 新建页不再要求先点击“生成内容规划”才能触发分镜生成。
- 仍保留 `480p`、`720p`、`1080p` 分辨率选项。
- 默认分镜数量保持 6。

回归测试：

- `node mvp/verify-core.js`
- `node mvp/verify-app.js`
- `node mvp/verify-server.js`
- `npm run verify`

## 验收标准

- 用户只输入一次内容规划想法，就能点击一个按钮生成分镜。
- 默认生成 6 个分镜。
- 旧内容规划不会在输入想法变化后被误用。
- `480p` 请求不再出现大小写或格式错误。
- `720p`、`1080p` 现有行为不回退。
- Fast 模型不支持某个分辨率时，不做本地降级，接口错误能被保留并展示。
